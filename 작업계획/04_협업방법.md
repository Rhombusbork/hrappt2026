# 협업 방법

세 사람이 같은 저장소(`Rhombusbork/hrappt2026`)를 고친다. 구조 담당은 VS Code의 Claude Code를 쓰고, A와 B는 웹 Claude Code(claude.ai/code)를 쓴다.

## 1. 시작 전 준비 (한 번만)

1. 저장소 주인이 GitHub에서 **Settings → Collaborators**로 A와 B를 초대한다.
2. A와 B는 claude.ai/code에서 GitHub를 연결하고 `Rhombusbork/hrappt2026`를 고른다.
3. 저장소 주인이 **Settings → Pages**에서 `main` 브랜치의 루트(`/`)를 배포하도록 켠다. 그러면 `https://rhombusbork.github.io/hrappt2026/`에서 합쳐진 결과를 볼 수 있다.
4. 구조 담당이 1단계를 `main`에 올린 **뒤에** A와 B가 시작한다. 1단계 전의 코드는 슬라이드 번호가 곳곳에 박혀 있어서, 그 위에서 고치면 거의 다 충돌한다.

## 2. 브랜치와 PR

| 누가 | 브랜치 이름 | PR 단위 |
|---|---|---|
| 구조 담당 | `structure` | 1단계 전체 한 번 |
| A | `fx-a/<연출이름>` 예: `fx-a/cover` | 연출 하나에 PR 하나 |
| B | `fx-b/<연출이름>` 예: `fx-b/banners` | 연출 하나에 PR 하나 |

- PR은 작게 자주 올린다. 연출 하나가 끝나면 바로 올린다.
- PR 설명에는 바꾼 파일, 새로 넣은 그림과 출처, 확인한 방법(어떤 화면에서 어떤 버튼을 눌렀는지)을 적는다.
- 구조 담당이 PR을 보고 합친다. 고칠 점은 PR 댓글로 남기고, A·B는 웹 Claude에게 "PR 댓글대로 고쳐 줘"라고 하면 된다.

## 3. 파일 규칙

충돌을 막으려고 연출마다 파일을 따로 두었다. **자기 연출 파일만 고친다.**

```
effects/
  cover.js        cover.css          ← A
  owl-letter.js   owl-letter.css     ← A
  invite-close.js invite-close.css   ← A
  awards.js       awards.css         ← A
  banners.js      banners.css        ← B
  blackout.js     blackout.css       ← B
  film.js         film.css           ← B
  capsule.js      capsule.css        ← B
  door.js         door.css           ← B
  starfall.js     starfall.css       ← B
assets/
  a/   ← A가 새로 넣는 그림
  b/   ← B가 새로 넣는 그림
  출처.md ← 새 그림의 주소와 라이선스 (둘 다 한 줄씩 추가)
photos/activity/ ← 필름에 들어갈 활동 사진 (B가 시연용으로 채움)
```

- `index.html`에는 위 파일이 이미 모두 연결되어 있다. 새로 연결할 필요가 없다.
- `stage.js`, `stage.css`, `slides.js`, `index.html`은 고치지 않는다. 꼭 고쳐야 하면 PR 설명에 이유를 쓰고 구조 담당에게 알린다.
- 예외: `assets/출처.md`는 두 사람 모두 줄을 추가한다. 충돌이 나도 두 줄을 다 남기면 된다.

## 4. 연출 파일 쓰는 법

연출 파일은 `HRA_EFFECTS`에 자기 이름으로 객체 하나를 등록한다. 슬라이드가 화면에 그려진 뒤 `enter`가 불리고, 사회자가 **장면 진행**(스페이스바)을 누르면 `cue`가 불린다.

```js
// effects/banners.js
(window.HRA_EFFECTS ||= {}).banners = {
  // 슬라이드에 들어올 때. slide는 <section class="slide">, api는 아래 표 참고.
  enter(slide, api) {
    // 필요한 요소를 slide 안에 추가하거나, 이미 있는 요소에 클래스를 붙인다.
    // 정리할 것이 있으면 함수를 돌려준다(슬라이드를 떠날 때 불림).
    return () => {};
  },
  // 장면 진행 버튼을 눌렀을 때. true를 돌려주면 기본 동작(단계 공개 등)을 하지 않는다.
  cue(slide, api) {
    return false;
  },
};
```

| `api` | 뜻 |
|---|---|
| `api.next()` | 다음 슬라이드로 넘어간다 |
| `api.reduced` | 사용자가 움직임 줄이기를 켰으면 `true`. 이때는 애니메이션 없이 결과만 보여 준다 |
| `api.step` | 지금까지 공개된 단계 수(배너·학생증·양피지처럼 단계가 있는 슬라이드) |
| `api.wait(ms)` | `ms` 밀리초 기다리는 Promise |
| `api.reveal()` | 숨겨 둔 `.reveal-target`을 공개한다. 연출이 끝난 뒤 제목을 보여 줄 때 쓴다(필름, 문) |
| `api.id` | 지금 슬라이드의 `id` |
| `api.from` | 바로 전에 그려진 슬라이드의 `id`. 같은 슬라이드를 다시 그리면 자기 `id`가 된다 |

큐를 누르면 이 순서로 처리된다. 앞에서 처리되면 뒤는 하지 않는다.

1. 연출의 `cue()`가 `true`를 돌려주면 끝
2. 공개 전이면 `.reveal-target`을 공개한다
3. 남은 단계가 있으면 다음 `[data-step]`을 공개한다
4. 화면 안의 `[data-cue]` 버튼(타이머 시작, 답안 확정)을 누른다

### 단계가 있는 슬라이드

배너(4개), 학생증(내빈 수), 수상자 양피지(수상자 수)는 구조 쪽에서 이미 단계 기능을 만들어 두었다.

- 단계 요소에는 `data-step` 속성이 있다.
- 장면 진행을 누를 때마다 다음 요소에 `.is-shown`이 붙는다.
- 가장 최근에 공개된 요소에는 `.is-current`가 붙는다.
- 연출 쪽은 **`.is-shown`이 붙을 때의 CSS 애니메이션만** 쓰면 된다.

```css
/* effects/banners.css 예시 */
.slide[data-id=houses] .banner{ translate:0 -110%; }
.slide[data-id=houses] .banner.is-shown{ translate:0 0; transition:translate 1.1s cubic-bezier(.2,.9,.25,1.15); }
```

### CSS 규칙

- 선택자는 반드시 `.slide[data-id=<슬라이드 id>]`로 시작한다. 다른 슬라이드에 새어 나가지 않게 하려는 것이다.
- 크기는 `cqw`(화면 폭의 1%) 단위로 쓴다. 창 크기와 전체화면에서 비율이 같게 유지된다.
- `@media (prefers-reduced-motion: reduce)`에서는 애니메이션을 끄고 마지막 모습만 보여 준다.
- 글꼴은 따로 지정하지 않는다. 한글은 Pretendard, 영문은 Paperozi가 자동으로 적용된다.

## 5. 확인 방법

- 웹 Claude Code는 화면을 직접 띄우기 어렵다. PR을 올리기 전에 웹 Claude에게 headless Chrome이나 Playwright로 해당 슬라이드를 캡처해 보라고 하면 된다.
- 주소로 원하는 상태를 바로 열 수 있다.
  - `index.html#p4`: 4번 슬라이드
  - `index.html?cues=3#p4`: 4번 슬라이드에서 장면 진행을 0.4초 간격으로 3번 누른 상태
  - `index.html?scores=120,80,60,40#p18`: 점수를 바꾼 상태(저장하지 않음)
  - `index.html#opening`: 예비 슬라이드
- headless Chrome은 가상 시간 때문에 애니메이션 중간이 찍히는 일이 있다. 연출이 끝난 모습을 확인하려면 `--force-prefers-reduced-motion`을 붙여 찍는다. 그래서 움직임 줄이기 모드에서도 마지막 모습이 제대로 나와야 한다. 움직임 자체는 Playwright로 시간을 나눠 여러 장 찍어 확인한다.
- 합쳐진 뒤에는 GitHub Pages 주소에서 확인한다.
- 확인할 것
  - 창 크기, 전체화면(`F`), 좁은 화면에서 깨지지 않는가
  - 장면 진행을 끝까지 눌렀을 때 멈추거나 오류가 나지 않는가
  - 앞뒤로 넘겼다가 다시 와도 처음부터 다시 되는가
  - 브라우저 콘솔에 오류가 없는가

## 6. 웹 Claude Code에 처음 줄 지시문

A는 아래 글을 그대로 붙여 넣는다. B는 `02_연출_A.md`를 `03_연출_B.md`로, `fx-a`를 `fx-b`로 바꾼다.

```
이 저장소는 송년회 발표용 HTML 슬라이드다.
먼저 작업계획/00_전체계획.md, 작업계획/04_협업방법.md, 작업계획/02_연출_A.md를 읽어라.
02_연출_A.md의 표 순서대로 연출을 하나씩 만든다.
연출 하나가 끝날 때마다 fx-a/<연출이름> 브랜치로 PR을 올린다.
04_협업방법.md의 파일 규칙을 지키고, 자기 연출 파일 외의 파일은 고치지 마라.
화면 문구는 00_전체계획.md의 표에 있는 그대로 쓰고, 문구를 새로 지어내지 마라.
그림이 필요하면 저장소에 있는 그림을 먼저 쓰고, 없으면 무료 그림(CC0, CC BY)을 찾거나 SVG로 그린다. 새 그림의 출처는 assets/출처.md에 적는다.
```
